# routecheck

Утилита командной строки, которая отвечает на вопрос **«почему этот IP доступен из одной страны или сети, но не из другой, и где именно ломается маршрут»**.

Она проверяет адрес с вашего компьютера и из других стран, выясняет, чья это сеть и как она подключена к интернету, и показывает маршрут как цепочку организаций: *ваш провайдер → транзитные сети → точки обмена трафиком → сеть цели*. В конце даёт вывод простыми словами.

Работает на Windows, macOS и Linux, нужен только Python: сторонние библиотеки не нужны. Использует только бесплатные открытые источники.

## Что умеет

**Проверки маршрута**
- С вашего компьютера: ping, подключение к TCP-порту, проверка пакетов 1500 байт (MTU) и traceroute с владельцем каждого узла.
- Из других стран, городов и провайдеров через [Globalping](https://globalping.io): трассировки по ICMP и, если указан порт, по TCP. Обе выполняются с одних и тех же проб, поэтому их можно честно сравнивать.
- Обратный путь: трассировка из сети цели к вам. Маршруты в интернете почти всегда несимметричны, и проблема бывает именно на обратном пути.

**Сведения о сети**
- Владелец, страна регистрации и адрес для жалоб (abuse) из нужного регистратора (RIPE, ARIN, APNIC и т.д.).
- Где находится адрес по данным нескольких баз геолокации, с указанием расхождений.
- Какое место провайдер занимает в своей стране по числу пользователей.
- Состояние маршрута в мировой таблице: кто его видит и подписан ли он (RPKI).

**Как сеть подключена к интернету**
- Через каких провайдеров сеть выходит в мир и в каких долях.
- Как сеть видна из нужных стран: цепочки сетей по данным коллекторов RIPE RIS в Москве, Франкфурте, Барселоне и других городах.
- Точки обмена трафиком (DE-CIX, ESpanix, MSK-IX и др.) на пути: какая точка и чей это порт.

**Выводы**
- Обрыв внутри сети цели, у её соседа или на транзите.
- На каком стыке сетей ломается маршрут, если сравнить работающие и неработающие трассы.
- Ping доходит, а подключение к порту нет: блокируют порт или протокол, сам маршрут исправен.
- Маршрут не проходит проверку RPKI, анонс виден не всем, весь трафик идёт через единственного провайдера.
- Базы геолокации расходятся в стране: частая причина ложной геоблокировки.
- Полноразмерные пакеты теряются (проблема MTU).

## Пример отчёта

```text
$ python3 routecheck.py 87.124.192.1 -f RU -r DE --reverse --no-local

87.124.192.1 · Vodafone Espana (AS12430), ES

⚠ ИТОГ
  Сеть Vodafone Espana доступна из всех точек проверки (2), но сам адрес не отвечает. Скорее всего, на нём нет устройства или оно не отвечает на такие запросы.

ЧЬЯ СЕТЬ
  Владелец:  Vodafone Espana (AS12430), юрлицо VODAFONE ESPANA S.A.U., зарегистрирован в ES
  Жалобы:    abuse@corp.vodafone.es
  Где:       Barcelona, ES (MaxMind GeoLite, ip-api.com, ipwho.is); Madrid, ES (ipapi.co)
  Размер:    5-й провайдер ES, около 10% пользователей
  Сеть:      87.124.192.0/18, её видят 322 из 323 точек наблюдения RIPE RIS, маршрут подписан (RPKI valid)

КАК СЕТЬ ПОДКЛЮЧЕНА К ИНТЕРНЕТУ
  Основные выходы: CW 56%, RETN 10%, Hurricane Electric 6%
  Как её видно из Frankfurt, DE:
    Zayo Infrastructure France → Vodafone Espana
    NTT America → CW → Vodafone Espana
    WIIT → GTT Communications → CW → Vodafone Espana
  Как её видно из Moscow, RU:
    Fiord Networks UAB → GTT Communications → CW → Vodafone Espana
    Rascom → Level 3 Parent → CW → Vodafone Espana
    Inetcom Carrier → Hurricane Electric → Vodafone Espana

ПРОВЕРКИ МАРШРУТА
  ⚠ Moscow, RU (Timeweb) · ping
      Timeweb → RetnNet → RETN (64 мс)
      дошли до RETN, соседа сети Vodafone Espana; дальше адрес не ответил. Маршрут до сети, скорее всего, в порядке
  ⚠ Saint Petersburg, RU (Selectel) · ping
      Selectel → Arelion Sweden → CW (52 мс)
      дошли до CW, соседа сети Vodafone Espana; дальше адрес не ответил. Маршрут до сети, скорее всего, в порядке

ОБРАТНЫЙ ПУТЬ: от сети цели к вам (203.0.113.10, Ваш провайдер)
  ✔ Anguciana, ES (Vodafone) · ping
      Vodafone Espana → точка обмена DE-CIX Madrid → Ваш провайдер (16 мс)
      дошли до вашего провайдера (Ваш провайдер); дальше молчит ваш роутер или NAT провайдера, это нормально

Подробно по каждому узлу: --details, сырые данные: --json
```

Это реальный прогон, сокращённый. Адрес и провайдер автора в обратном пути заменены.

**Что видно из этого отчёта.** Из России обе трассы дошли до прямых соседей Vodafone (RETN и CW), то есть маршрут до сети исправен. Не отвечает только конкретный адрес. Обратно Vodafone отдаёт трафик через точку обмена DE-CIX в Мадриде.

## Установка

Нужен **Python 3.10 или новее** на **Windows, macOS или Linux**. Сторонние библиотеки не нужны.

### macOS и Linux

```bash
git clone https://github.com/saifutdinov/routecheck.git
cd routecheck
python3 routecheck.py 1.1.1.1
```

Проверить версию Python:

```bash
python3 --version
```

Для локальных проверок нужны системные `ping` и `traceroute`. На macOS они есть всегда. На Linux `traceroute` иногда приходится поставить: `sudo apt install traceroute` (Debian/Ubuntu) или `sudo dnf install traceroute` (Fedora). Без них можно работать только с удалёнными проверками (`--no-local` и `-f`).

### Windows

1. Установите Python 3.10 или новее. Проще всего так (в PowerShell):

   ```powershell
   winget install Python.Python.3.14
   ```

   Или скачайте установщик с [python.org](https://www.python.org/downloads/windows/) и отметьте «Add python.exe to PATH».

2. Скачайте утилиту. С установленным [Git](https://git-scm.com/download/win):

   ```powershell
   git clone https://github.com/saifutdinov/routecheck.git
   cd routecheck
   ```

   Без Git: на странице репозитория нажмите **Code → Download ZIP** и распакуйте архив.

3. Запустите через `py` (лаунчер Python для Windows):

   ```powershell
   py routecheck.py 1.1.1.1
   ```

Во всех примерах ниже на Windows пишите `py` вместо `python3`.

Особенности Windows:
- Локальные проверки используют встроенные `ping` и `tracert`, права администратора не нужны. Вывод разбирается одинаково на русской и английской Windows.
- `tracert` медленнее, чем `traceroute` на macOS и Linux: до цели в 15 узлов локальная трассировка может занять минуту и больше. Если локальная часть не нужна, добавьте `--no-local`.
- Отчёт выводится в UTF-8. В Windows Terminal и современной консоли значки ✔ ⚠ ✖ и стрелки отображаются нормально. Сохранить отчёт в файл проще всего из `cmd`: `py routecheck.py 1.1.1.1 > report.txt`. В старом Windows PowerShell 5.1 перенаправление `>` портит кодировку, там перед запуском выполните:

  ```powershell
  [Console]::OutputEncoding = [Text.Encoding]::UTF8
  ```

Также работает в WSL, как на обычном Linux.

### Через mise и uv (для разработки)

В репозитории закреплены версии инструментов (`mise.toml`) и зависимости для тестов (`uv.lock`):

```bash
mise install
uv sync
uv run routecheck.py 1.1.1.1
```

Команды запускайте из папки `routecheck`: вне её mise не знает, какую версию uv использовать.

## Быстрый старт

Проверить адрес только со своего компьютера:

```bash
python3 routecheck.py example.com
```

Проверить ещё из Германии и России, включая порт 443 (HTTPS):

```bash
python3 routecheck.py example.com -p 443 -f DE -f RU
```

То же и с обратным путём от сети цели к вам:

```bash
python3 routecheck.py example.com -p 443 -f DE -f RU --reverse
```

Обычная проверка занимает 15-60 секунд: трассировки из других стран идут через внешний сервис.

## Типовые задачи

### «Из одной страны открывается, из другой нет»

Проверьте из обеих стран сразу, обязательно с портом сервиса:

```bash
python3 routecheck.py 203.0.113.5 -p 443 -f DE -f RU -n 3
```

`-n 3` берёт по три пробы в каждой стране, чтобы случайный сбой одной пробы не исказил картину. На что смотреть:
- **Ping доходит, а порт нет**, особенно только из одной страны: фильтрация на пути (в России ТСПУ) или геоблокировка на стороне сервиса.
- **Обрыв на стыке сетей**: утилита назовёт, до какой сети доходит трафик и какая сеть идёт следующей в работающих маршрутах.
- **Базы геолокации расходятся в стране**: сервис мог ошибочно заблокировать адрес как «чужой».

### Проверить конкретного провайдера

`-f` понимает страны, города, номера сетей (ASN), названия провайдеров и их сочетания через `+`:

```bash
python3 routecheck.py 203.0.113.5 -f "RU+Rostelecom" -f AS8359 -f "Moscow+MTS" -f "ES+Vodafone"
```

Если подходящих проб нет совсем, Globalping вернёт ошибку, и утилита покажет её в конце отчёта. Тогда попробуйте страну или город вместо конкретного провайдера.

### Понять, как связаны две сети

Например, как трафик идёт между Ростелекомом и Vodafone Испания:

```bash
python3 routecheck.py 87.124.192.1 -f "RU+Rostelecom" -r RU -r ES --reverse --no-local
```

- `-f "RU+Rostelecom"`: трассировка из Ростелекома к Vodafone.
- `-r RU -r ES`: как сеть Vodafone видна из России и Испании по таблицам маршрутизации.
- `--reverse`: трассировка из Vodafone обратно к вам.

### Подозрение на обратный путь

Если трассировка туда выглядит нормально, а соединения всё равно нет, проверьте путь обратно:

```bash
python3 routecheck.py 203.0.113.5 --reverse
```

Без значения `--reverse` трассирует к вашему внешнему IP. Можно указать любой адрес, например сервер, с которого ничего не работает:

```bash
python3 routecheck.py 203.0.113.5 --reverse 198.51.100.20
```

Пробы ищутся сначала внутри сети цели, затем в её стране.

### Посмотреть, как сеть видна из нужных стран

Трассировки не нужны, только таблицы маршрутизации и сведения о сети:

```bash
python3 routecheck.py 203.0.113.5 --no-local -r DE -r FR -r ES
```

### Подготовить обращение к провайдеру

Провайдеры (NOC) просят прислать трассировки и время проверки. Полный отчёт с таблицами узлов:

```bash
python3 routecheck.py 203.0.113.5 -p 443 -f DE -f RU --reverse --details > report.txt
```

Адрес для обращения указан в отчёте в строке «Жалобы». Контакты сетевого отдела ищите в [PeeringDB](https://www.peeringdb.com).

### Использовать в скриптах

`--json` выводит все собранные данные. Код выхода `0`, если все трассировки дошли до адреса, и `1`, если нет:

```bash
python3 routecheck.py 203.0.113.5 -f DE --no-local --json | jq '.headline'
```

```bash
python3 routecheck.py 203.0.113.5 -p 443 || echo "адрес недоступен"
```

## Как читать отчёт

### Разделы

| Раздел | Что в нём |
|---|---|
| **ИТОГ** | Ответ одной фразой по всем проверкам |
| **ЧЬЯ СЕТЬ** | Владелец, контакт для жалоб, местоположение по разным базам, доля рынка, состояние маршрута |
| **КАК СЕТЬ ПОДКЛЮЧЕНА К ИНТЕРНЕТУ** | Через кого сеть выходит в мир и цепочки сетей, которыми её видят из нужных стран |
| **ПРОВЕРКИ МАРШРУТА** | Каждая трассировка цепочкой организаций, задержка и объяснение результата |
| **ОБРАТНЫЙ ПУТЬ** | Трассировки из сети цели к вам (с `--reverse`) |
| **ЧТО ЕЩЁ ЗАМЕТИЛИ** | Найденные проблемы и подозрения |

### Значки

| Значок | Значение |
|---|---|
| ✔ | Всё работает |
| ⚠ | Работает частично или есть оговорка: маршрут до сети исправен, но адрес молчит, или есть потери |
| ✖ | Не работает |
| ℹ | Маршрут не проверялся |

### Что означают выводы

| Вывод | Что это значит | Что делать |
|---|---|---|
| *адрес отвечает, потерь нет* | Всё в порядке | Если сервис всё равно не работает, проверьте порт (`-p`) |
| *дошли до сети X, но сам адрес не ответил* | Маршрут исправен, не отвечает устройство | Адрес выключен, не существует или не отвечает на ping. Проверьте порт сервиса |
| *дошли до соседа сети цели* | Трафик дошёл до провайдера, который передаёт трафик в сеть цели | Обычно то же самое: маршрут в порядке, молчит адрес или граница сети |
| *обрыв: последний ответ от сети X* | Пакеты пропадают после сети X | Сравните с работающими трассами. Обращайтесь к сети X или к следующей за ней |
| *ping доходит, а подключение к порту нет* | Маршрут исправен, блокируют порт или протокол | Фильтрация на пути, файрвол или геоблок у сервиса, закрытый порт |
| *теряется N% пакетов, начиная с сети X* | Сеть X перегружена или сбоит | Если потери держатся до самого адреса, это реальная проблема |
| *дошли до вашего провайдера, дальше молчит роутер* | Обратный путь в порядке | Ничего: домашние роутеры и NAT часто не отвечают на ping |

### Частые вопросы

**На промежуточном узле 60% потерь, а до цели 0%. Это проблема?**
Нет. Роутеры отвечают на трассировку по остаточному принципу и часто ограничивают такие ответы. Реальная проблема только та, где потери начинаются и держатся до самого адреса. Утилита это различает.

**Почему узлы с адресами 10.x, 172.16-31.x, 192.168.x без названия сети?**
Это внутренние адреса провайдеров, они не принадлежат никому в публичном интернете. Утилита относит их к последней известной сети на пути.

**Почему трассировка туда и обратно идёт через разные сети?**
Это нормально. Каждая сеть сама выбирает, куда отправлять трафик, поэтому пути туда и обратно обычно разные. Из-за этого проверять стоит оба направления.

**Почему базы геолокации показывают разные города?**
У каждой базы свои источники и методы, и для сетей провайдеров город часто определяется приблизительно. Плохо, когда базы расходятся в **стране**: тогда сервисы с геоблокировкой могут ошибаться. Утилита об этом предупреждает.

**Что такое «точка наблюдения RIPE RIS»?**
Это маршрутизатор-коллектор на крупной точке обмена трафиком, который собирает таблицы маршрутизации от сотен сетей. Если маршрут к адресу видят не все, часть интернета просто не знает, куда отправлять пакеты.

## Все параметры

```text
python3 routecheck.py АДРЕС [параметры]
```

| Параметр | Что делает |
|---|---|
| `АДРЕС` | IPv4-адрес или имя хоста |
| `-p`, `--port ПОРТ` | Проверить подключение к TCP-порту, например `443`. Удалённые пробы делают ещё и трассировку по TCP |
| `-f`, `--from МЕСТО` | Откуда проверять: страна (`DE`, `Germany`), город (`Madrid`), сеть (`AS12389`), провайдер (`Rostelecom`) или сочетание через `+` (`Moscow+MTS`). Можно указать несколько раз |
| `-n`, `--probes N` | Сколько проб брать на каждое место из `-f`. По умолчанию 2 |
| `-r`, `--region КОД` | Показать, как сеть видна из страны (двухбуквенный код, `RU`, `DE`, `ES`). Страна цели и двухбуквенные коды из `-f` добавляются сами. Можно указать несколько раз |
| `--reverse [IP]` | Трассировать из сети цели обратно. Без значения: к вашему внешнему IP |
| `--max-hops N` | Максимум узлов в локальной трассировке. По умолчанию 30 |
| `--no-local` | Не делать проверок с этого компьютера |
| `-v`, `--details` | Добавить таблицы по каждому узлу, сырые данные геолокации и все цепочки сетей |
| `--json` | Вывести все данные в JSON вместо отчёта |

### Переменные окружения

| Переменная | Зачем |
|---|---|
| `GLOBALPING_TOKEN` | Токен [Globalping](https://globalping.io): больше проверок в час, чем анонимно |
| `IPINFO_TOKEN` | Токен [IPinfo](https://ipinfo.io/lite): добавляет IPinfo Lite к сравнению геолокации |

```bash
export GLOBALPING_TOKEN=ваш_токен
```

## Откуда берутся данные

Все источники бесплатные и работают без регистрации, кроме двух необязательных токенов выше.

| Источник | Что даёт |
|---|---|
| Системные `ping`, `traceroute` | Локальные проверки и трассировка |
| [Globalping](https://globalping.io) | Трассировки (mtr) из тысяч точек по всему миру |
| [RIPEstat](https://stat.ripe.net) | Сеть и её номер (ASN), видимость маршрута, RPKI, соседи сети, таблицы коллекторов RIPE RIS, база MaxMind GeoLite |
| [rdap.org](https://rdap.org) | Запись о регистрации из нужного регистратора: владелец, страна, abuse-контакт |
| [Team Cymru](https://www.team-cymru.com/ip-asn-mapping) | Владелец каждого узла трассировки, названия сетей |
| [PeeringDB](https://www.peeringdb.com) | Точки обмена трафиком и чьи на них порты |
| [APNIC Labs](https://stats.labs.apnic.net/aspop) | Крупнейшие провайдеры страны и их доля пользователей |
| [ip-api.com](https://ip-api.com), [ipapi.co](https://ipapi.co), [ipwho.is](https://ipwho.is) | Геолокация для сравнения |
| [ipify](https://www.ipify.org) | Ваш внешний IP (только с `--reverse` без значения) |

Если какой-то источник недоступен или ограничил запросы, отчёт строится без него, а в конце указано, чего получить не удалось.

---

## Что уходит наружу

Утилита ничего не сохраняет и никуда не отправляет, кроме запросов к источникам выше. Учитывайте:
- **проверяемый адрес** уходит во все перечисленные сервисы;
- **с `--reverse`** ваш внешний IP уходит в ipify и Globalping: пробы Globalping трассируют до него;
- **трассировки Globalping** видны в их API по идентификатору проверки.

Не проверяйте этой утилитой адреса, которые нельзя раскрывать третьим сторонам.

---

## Ограничения

- **Только IPv4.**
- **Локальная трассировка идёт по ICMP.** TCP-трассировка требует прав администратора, поэтому по TCP трассируют только удалённые пробы (`-p` вместе с `-f`).
- **Лимиты сервисов.** Анонимно Globalping даёт ограниченное число проверок в час, ipapi.co и ip-api.com тоже ограничивают частоту. Каждая проба из `-n` и каждый протокол расходуют лимит Globalping.
- **Подписи проб Globalping иногда неточны.** Проба с меткой провайдера может на деле выходить в интернет через другого.
- **Геолокация приблизительна**, особенно для сетей провайдеров и anycast-адресов (Cloudflare, Google и т.п.).
- **Данные APNIC Labs о долях пользователей** получены статистически и для некоторых стран выглядят странно. Например, по России в верхних строках оказываются сети Крыма и ДНР.
- **Пробы есть не везде.** В некоторых сетях Globalping пробы нет. Тогда обратный путь строится из страны цели, а не из её сети.

## Разработка

```bash
mise install
uv sync
uv run pytest
ruff check . && ruff format --check .
```

Весь код в одном файле `routecheck.py`, тесты в `test_routecheck.py`. Логика анализа (разбор трассировок, вердикты, сравнение маршрутов, названия сетей) написана чистыми функциями и покрыта тестами без сетевых запросов. Разбор вывода `ping`, `traceroute` и `tracert` проверяется на образцах macOS, Linux и Windows (русская и английская локали).

GitHub Actions прогоняет тесты и пробный запуск с локальными проверками на Windows, macOS и Linux, на Python 3.10 и 3.14.
